# Платформы

Какую сборку взять, что она умеет и где не умеет.

Clickwork — одна программа на двух платформах. Окно, редактор, скриптовый движок, поиск по
картинке и чтение текста — один и тот же код; под ними лежат два платформенных слоя,
совершенно непохожих, а Linux добавляет вторую ось, которой у Windows нет вовсе, —
композитор.

Всё, против чего в этом файле стоит число, **измерено** на названной машине или в названном
сеансе, а не выведено из описания протокола. Где не измерено — так и написано.

## Windows против Linux, возможность за возможностью

**Обозначения.** ● работает · ◐ работает с условием, названным в примечании · ○ не работает

| | Windows 11 | Linux | Примечание |
|---|:---:|:---:|---|
| **Запись** | | | |
| Мышь и клавиатура | ● | ● | Windows — низкоуровневые хуки; Linux читает устройства ввода напрямую, ниже композитора |
| Где находится указатель | ● | ◐ | Linux: только Hyprland. В остальных никто не скажет, поэтому движения и клики не записываются по координате — стройте шаги мыши на привязках к картинке или элементу |
| Ввод, адресованный другим приложениям | ● | ● | На Linux ради этого evdev и читается |
| Ввод, который проглотил композитор | ○ | ● | evdev лежит ниже композитора и видит клавиши, которых не получает ни одно приложение |
| **Воспроизведение** | | | |
| Мышь | ● | ◐ | Все измеренные композиторы, кроме COSMIC |
| Клавиатура, записанные клавиши | ● | ● | На KDE это даже **вернее**: KWin трактует клавишу под раскладкой пользователя, без зеркалирования keymap, которое нужно пути wlroots |
| Набор произвольного текста | ● | ◐ | Не на KDE — см. *Пробелы* ниже |
| В окно с повышенными правами | ○ | — | Windows запрещает это наглухо, и обойти изнутри программы нельзя. На Linux такого барьера нет |
| **Взгляд на экран** | | | |
| Поиск по картинке, OCR, условие по пикселю | ● | ◐ | Не на COSMIC и не на GNOME |
| Сокращение «ничего не изменилось» | ● | ○ | Desktop Duplication сообщает о повреждённых областях, и неизменившийся экран не стоит ничего. Ни у одного протокола захвата Wayland такого сигнала нет — каждый взгляд настоящая копия |
| Второй путь захвата на случай отказа | ● | ○ | У Windows Desktop Duplication и GDI. У Linux одна дорога на композитор |
| **Окна** | | | |
| Перечислить, сфокусировать, закрыть | ● | ◐ | Hyprland, KWin и все композиторы wlroots. Не COSMIC, не GNOME |
| Геометрия, без которой не работают привязки | ● | ◐ | Только Hyprland и KWin |
| Процесс за окном | ● | ◐ | Только Hyprland и KWin |
| Переместить, изменить размер, отцентровать | ● | ◐ | Только Hyprland |
| Изоляция рабочих столов | ● | ◐ | Только Hyprland и KWin. Ни один протокол wlroots не говорит, на каком столе окно |
| **Остальное** | | | |
| Шаги по элементам интерфейса | ● | ◐ | UI Automation достаёт Win32, WPF, UWP и Electron широко; AT-SPI достаёт то, что тулкит решил показать, и требует начала координат окна — то есть бэкенда, который измеряет |
| Распознавание текста | ● | ● | Windows своим OCR; Linux открывает Tesseract на лету |
| Сквозной оверлей | ● | ◐ | layer-shell. Есть у всех измеренных композиторов, кроме GNOME |
| Иконка в трее, уведомления | ● | ● | StatusNotifierItem и шина уведомлений freedesktop |
| Буфер обмена без фокуса | ● | ◐ | data-control. Нет на GNOME |
| Горячие клавиши | ● | ◐ | См. следующую строку |
| Горячие клавиши, которые **проглатывают** клавишу | ● | ◐ | Низкоуровневый хук её съедает. На Linux это умеет только бинд композитора; Hyprland их получает, в остальных клавиша дойдёт и до приложения впереди |
| Запись экрана во время прогона макроса | ● | ◐ | На Windows внутри процесса. На Linux вызывает `gpu-screen-recorder` или `wf-recorder`, а без них не делает ничего |
| Выключение, перезагрузка, сон, выход | ● | ● | `sudo` на systemd-десктопе не нужен: polkit уже разрешает это сидящему за машиной |
| Показатель отзывчивости окна | ● | ○ | Он измерялся прогоном сообщения через очередь целевого окна. На Wayland такой очереди нет |
| Mica и Acrylic | ● | ○ | Темы *Fluent* и *Glass* рисуют собственную полупрозрачность |
| Самозапускающийся экспортированный плеер | ● | ● | `.exe` на Windows, ELF без расширения на Linux — работают оба |
| Экспорт в AutoHotkey | ● | ● | Это формат Windows в любом случае, но файл создаётся на обеих |

### Из чего это сделано

| | Windows | Linux |
|---|---|---|
| Воспроизведение | `SendInput` | `zwlr_virtual_pointer_v1` + `zwp_virtual_keyboard_v1`, либо `org_kde_kwin_fake_input` на KDE |
| Запись | `WH_MOUSE_LL`, `WH_KEYBOARD_LL` | evdev, `/dev/input/event*` |
| Захват | Desktop Duplication, GDI | `zwlr_screencopy_v1`, либо `org.kde.KWin.ScreenShot2` на KDE |
| Окна | функции окон Win32 | IPC Hyprland, `org_kde_plasma_window_management` либо `zwlr_foreign_toplevel_management_v1` |
| Элементы | UI Automation | AT-SPI2 по D-Bus |
| Распознавание текста | `Windows.Media.Ocr` | Tesseract 5, открывается на лету |
| Оверлей | слоёное окно, GDI | `zwlr_layer_shell_v1` |
| Трей | `Shell_NotifyIcon` | StatusNotifierItem по D-Bus |
| Единственный экземпляр | именованный мьютекс | Unix-сокет в `$XDG_RUNTIME_DIR` |
| Настройки | `%APPDATA%\Clickwork` | `~/.config/clickwork` |

### Тесты

| | |
|---|---|
| Windows | **292** теста, на настоящем раннере Windows в CI |
| Linux | **315** тестов плюс пятнадцать проверок возможностей против живого композитора |

Лишние тесты на Linux — это платформенный слой; пятнадцать проверок — это
`--selftest session`, который спрашивает каждую возможность дважды (объявлен ли протокол и
делает ли код) и падает, когда ответы расходятся.

## Какой пакет для Linux

Все четыре несут одну и ту же программу. Отличаются тем, что ставят вокруг неё, и тем, на
каком старом дистрибутиве запустятся.

| | `.deb` | `.rpm` | `.pkg.tar.zst` | `.tar.gz` |
|---|---|---|---|---|
| Для | Debian, Ubuntu, Mint | Fedora, RHEL, openSUSE | Arch, CachyOS, EndeavourOS | всего остального |
| Установка | `apt install ./clickwork_*.deb` | `dnf install ./clickwork-*.rpm` | `pacman -U clickwork-*.pkg.tar.zst` | распаковать и `./install.sh` |
| Зависимости разрешаются за вас | ● | ● | ● | ○ |
| Правило udev, без которого нет записи | ● | ● | ● | ◐ через `install.sh` |
| Desktop-файл — **обязателен на KDE** | ● | ● | ● | ◐ через `install.sh` |
| Иконки, документация | ● | ● | ● | ● |
| **Порог glibc** | **2.35** | **2.35** | ваш Arch | **2.35** |
| Достаёт до | Debian 12+, Ubuntu 22.04+ | Fedora 36+, RHEL 9+ | rolling | любой glibc 2.35+ |

**Порог glibc — единственное число, решающее, запустится ли пакет вообще.** glibc совместима
назад и не совместима вперёд, поэтому порог задаёт машина сборки, а не код. `.deb`, `.rpm` и
`.tar.gz` собираются в контейнере `debian:bookworm` именно поэтому: сборка на современном
rolling-дистрибутиве требует `GLIBC_2.43`, которую почти никто не везёт, — такой пакет чисто
установится на Debian 13, Ubuntu 24.04 и Fedora 41 и не запустится. CI сравнивает каждую
сборку с `packaging/glibc-floor` и валит ту, что превысила.

### Установка вручную

Tarball — для дистрибутивов без собственного пакета. Внутри бинарник, правило udev,
desktop-файл, иконки, документация и `install.sh`:

```bash
tar -xzf clickwork-*.tar.gz
cd clickwork-*
./install.sh          # в /usr/local, и он говорит, что делает
```

**Распаковать и запустить бинарник с места достаточно на большинстве композиторов и
недостаточно на KDE**, где программа должна быть установлена, чтобы KWin вообще выдал ей
оконный протокол и интерфейс скриншотов. `install.sh` пишет тот самый desktop-файл.

### Чего нет и почему

**Flatpak и Snap.** Не упущение. Клиент Wayland в песочнице видит 40 из 71 интерфейса,
которые объявляет этот сеанс, и среди недостающих — виртуальный указатель, виртуальная
клавиатура, screencopy, layer-shell и оба протокола data-control. То есть воспроизведение,
поиск по картинке, оверлей и буфер обмена. Ключа манифеста, который попросил бы обычный
сокет, не существует. Flatpak можно собрать, переведя ввод на `/dev/uinput`, и получится
Clickwork без оверлея, с более медленным захватом и всё равно с шагом выдачи прав на
стороне хоста — оно того пока не стоит.

**AppImage.** Возможен и не собран. Tesseract открывается на лету, а не линкуется, так что
AppImage пришлось бы решать, тащить его внутрь или нет.

## Композиторы

Каждая строка измерена одним и тем же бинарником и одними и теми же двумя командами —
`--selftest session` и `--doctor` — против этого композитора. Четыре из них целина: до
2026-09-20 программу на них не запускал никто.

| Композитор | Окна | Геометрия | Раб. столы | Захват | Воспроизв. | Оверлей | Проверки |
|---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| **Hyprland** 0.56.2 | ● | ● | ● | ● 6,0 мс | ● | ● | 15/15 |
| **KDE Plasma** (KWin 6.7.5) | ● | ● | ● | ● **2,0 мс** | ● | ● | 15/15 |
| **sway** 1.12 | ● | ○ | ○ | ● 16 мс | ● | ● | 15/15 |
| **niri** 26.04 | ● | ○ | ○ | ● | ● | ● | 15/15 |
| **river** 0.4.8 | ● | ○ | ○ | ● 16 мс | ● | ● | 15/15 |
| **Wayfire** 0.11.0 | ● | ○ | ○ | ● 16 мс | ● | ● | 15/15 |
| **labwc** 0.20.2 | ● | ○ | ○ | ● | ● | ● | 15/15 |
| **COSMIC** 1.8.0 | ○ | ○ | ○ | ○ | ◐ клавиатура | ● | 14/14 |
| **GNOME** (Mutter) | ○ | ○ | ○ | ○ | ○ | ○ | не измерялось |

Три вещи, которых таблица не показывает.

**Захват быстрее всего на KDE** — обратное тому, что подсказывает список протоколов: у KWin
screencopy нет вовсе, и он отвечает по D-Bus, а основная цена там — фиксированный обход, а
не пиксели, поэтому время почти не растёт от маленького прямоугольника до целого экрана.
Числа в 16 мс — это программно отрисованные безголовые сеансы, свойство стенда, а не
композитора.

**Hyprland по-прежнему единственный, кто отвечает на всё.** KWin ближе всех и не умеет найти
указатель и переместить окно; семейство wlroots перечисляет окна и управляет ими, но ничего
не измеряет. Программа говорит, что именно: `--doctor` печатает и `can …`, и `cannot …` для
того сеанса, в котором вы находитесь, — это самый быстрый ответ на «почему эта возможность
тут ничего не делает».

**COSMIC не хватает клиента, а не протокола.** cosmic-comp выбросил протоколы wlroots в
пользу стандартизованных преемников — `ext_foreign_toplevel_list_v1`,
`ext_image_copy_capture_manager_v1`, — на которых программа пока не говорит. Так что окна и
захват отсутствуют там по причине, исправимой в этом репозитории, а не в композиторе.

### Отдельно про KDE Plasma

KDE работает, с одним условием: **программа должна быть установлена.** KWin держит пять
интерфейсов Wayland вне реестра и отдаёт их только клиенту, чей путь разрешается в
desktop-файл, который их просит, и так же отказывает своему интерфейсу скриншотов. Бинарник
из каталога сборки или из распакованного вручную tarball не получает ни того, ни другого —
ни оконного бэкенда, ни захвата, — и `--doctor` прямо это говорит. Любой из четырёх пакетов
ставит desktop-файл, который это чинит.

## Пробелы, названные прямо

**Набор текста не работает на KDE.** Напечатать *символ*, а не нажать *позицию клавиши*,
можно только через `keyboard_keysym` — версия 6 интерфейса, а привязки протоколов, против
которых собрана программа, останавливаются на пятой. Отправить вместо этого позицию клавиши
значило бы напечатать другой символ на любой раскладке кроме `us`, поэтому программа
отказывается и говорит об этом. Воспроизведение записанных клавиш не затронуто.

**Записи по координате нужен Hyprland.** Больше никто не скажет, где указатель, поэтому ни
движения мыши, ни клики нигде больше не записываются: клик, записанный в углу, — это не
потерянный клик, а шаг, который на каждом воспроизведении жмёт угол. Записывайте
клавиатурой, а шаги мыши стройте на привязках к картинке или элементу — они для этого и
есть.

**У COSMIC нет оконного бэкенда и захвата**, как сказано выше.

**GNOME умеет запись и больше ничего.** Mutter не реализует ни одного протокола
foreign-toplevel, ни screencopy, ни виртуального указателя, ни виртуальной клавиатуры, ни
data-control, ни layer-shell. Запись работает, потому что evdev лежит ниже композитора.
Воспроизведение и поиск по картинке — нет, а AT-SPI дыру не закрывает: без начала координат
окна координаты элементов не «хуже», а неверны.

## Откуда взяты числа

| | |
|---|---|
| Hyprland | собственный сеанс машины разработчика, 71 интерфейс Wayland |
| KWin 6.7.5 | пакеты распакованы в отдельный каталог, `kwin_wayland --virtual`, ничего не установлено |
| sway 1.12 | `ci/headless-session.sh`, безголово, без видеоустройства |
| sway 1.9 | тот же скрипт на раннере GitHub, 44 интерфейса |
| niri, river, Wayfire, labwc, COSMIC | пакеты распакованы так же, безголово; у niri безголового режима нет, он измерен вложенным в безголовый sway |
| GNOME | здесь не измерялся — по исходникам протоколов и прежнему аудиту |
| Пакеты | собраны в `debian:bookworm` силами CI, а `.deb` установлен в чистый контейнер `debian:trixie` и запущен там |

`--selftest session` печатает всё это для того сеанса, в котором вы находитесь, и выходит с
ненулевым кодом, когда что-то с чем-то расходится.
